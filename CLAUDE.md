# Landslide inventory mapping, Pacitan (Cempaka 2017)

## Goal
Detect landslides triggered by Cyclone Cempaka (28 Nov to 1 Dec 2017) in Pacitan with a data science approach instead of manual digitizing. Success measured by: TBD (polygon-level precision, recall, IoU vs a reference inventory).
POC: do Satellite Embedding change features (2018 vs 2017) detect Cempaka landslides at least as well as a Sentinel-2 dNDVI baseline? Slice: 1 to 2 sub-districts, a few hundred labeled polygons, spatial train/test split. Pass / stop: embeddings beat dNDVI recall at similar precision, or catch slides it misses; drop if no better or only works above a size cutoff that loses most of the inventory (to be written as a script check). Out of scope until it passes: all of Pacitan, susceptibility mapping, pipeline, dashboard, other events.

## Data
- Sources: reference inventory = Samodra et al. (UGM), Mendeley Data DOI 10.17632/vrtx3w6mjd.1, CC BY 4.0 (credit authors). Mendeley page footer reserves text/data-mining and AI-training rights; read as site content, not checked against the dataset licence. Embeddings: Earth Engine GOOGLE/SATELLITE_EMBEDDING/V1/ANNUAL (2017 layer regenerated in v1.1; pin version, check live catalog for the upper year).
- Grain / key tables: `data/spatial/mendeley_vrtx3w6mjd/landslide_pacitan.gpkg`: 743 MultiPolygons, EPSG:32749, columns Id, kode, Area, X/Y_centroid. Also available, not downloaded: ls_center.gpkg, non_ls.gpkg, 11 factor rasters (~96 MB each).
- Inventory provenance (phase 1a, from the Data in Brief paper, Samodra et al. 2024, DOI 10.1016/j.dib.2024.111155, read from the author-accessible PDF; not committed): study area Pacitan Regency; polygons delineated manually on 50 cm imagery (Google Earth pre-event, Pleiades post-event via LAPAN; Pleiades date not stated) plus UAV; started from 328 BPBD citizen-report points, extended with imagery; field-verified. The paper itself says BPBD data miss small, remote or no-casualty slides, and states no wall-to-wall mapping footprint (Limitations: "None"). So absence of a polygon is not verified absence of a landslide. Land use = 1:25,000 digital topographic map polygons (no event-specific scars, year and class names not given); lithology = 1:100,000 Pacitan geological map (1992); DEM factors from DEMNAS. Licences: Mendeley dataset CC BY 4.0, the article CC BY-NC 4.0.
- Measured footprint (phase 1a): valid land-use pixels 1,418 km2 (regency-sized), all 743 centroids inside, 120 of 160 mostly-valid 3 km blocks hold >= 1 landslide (median 4); the 40 empty blocks are gentler (median 6% of pixels > 25 deg vs 15%) but 4 have 39 to 60% > 25 deg. Completeness unverified; the inventory author not reachable, so the rule below is used instead (map: reports/figures/inventory_coverage.png, script src/data/coverage_map.py).
- Phase 1 cleaning rule (set before the test carve; applies to training and evaluation): drop the 3 km blocks that have no polygon although the lithology-class landslide density predicts >= 4.6 (Poisson P(0) < 1%): 5 blocks (r8 c10, r9 c15, r9 c16, r9 c18, r10 c14), about 45 km2 (3% of the domain), about 36 expected missing slides (about 5% of the 743). Classes 7 and 32 have 82 to 88 slides per 100 km2. The 20-block south-west cluster of empty blocks is kept: 91% lithology class 8, the lowest density (17 per 100 km2), 7% steep, so real absence is plausible. Report results with and without the 5 blocks.
- Factor grid (phase 1b): all 11 rasters share one grid (EPSG:32749, 10 m, 5815 x 4051). Invalid pixels: land-use 9,374,705; others 9,374,809; geology 9,420,628 (45,923 px inside the land-use mask lack geology); twi 9,377,407. Check: src/data/check_grid.py.
- Known quirks: embeddings are annual (2017 is almost all pre-event; 2018 may be diluted by revegetation); 10 m pixels miss small slides: median polygon 1,068 m2, 15.9% under 3 px, 27.5% under 5 px. Extent is all of Pacitan (~43 x 39 km); landslides are ~0.13% of the bbox, so negatives must be sampled and pixel accuracy is meaningless.

## Decisions
- 2026-11-11: Project created. Type: modelling, spatial. Tools: geopandas, shapely, rasterio, pandas, matplotlib, earthengine-api (uv). scikit-learn added at the modelling step.
- 2026-11-11: Used the public Samodra inventory as labels (no need for the friend's data). Size check (`src/inventory_check.py`) done; pass/stop criteria unchanged. Report metrics at polygon and pixel level, split by size class (<5 px, 5 to 20 px, >20 px). Slice must shrink from all of Pacitan to one or two sub-districts.
- 2026-11-11: Embedding change check (cosine distance 2017->2018, point level, 743 landslide vs 743 background, AUC): random bg 0.725; slope+elevation matched 0.720; + land-use matched 0.705 (size classes 0.52 / 0.73 / 0.83 for <5 px / 5-20 px / >20 px). 2018->2019 control ~0.50. Risk still open: 2017 layer is v1.1, 2018 is v1.0, and background 17->18 change is ~2.1x a normal year (M3 fails every run).
- 2026-11-11: dNDVI baseline (S2 L1C + Cloud Score+, pre Aug-Oct 2017) on the same points: post Dec17-Mar18 AUC 0.698 (cloud-limited, tie with embeddings 0.704, diff +0.007, CI [-0.021, +0.037]); post Apr-May18 AUC 0.790, beats embeddings by 0.085 (CI [-0.116, -0.057]). Which post window counts as primary was not fixed beforehand; B2 should be read as requiring the CI to exclude zero. Unsupervised embedding distance is no better than dNDVI. Supervised use of embeddings untested.
- 2026-11-11: Supervised test (src/supervised_check.py; 742 landslide + 743 land-use/slope/elevation-matched background points, 5-fold CV over 3 km blocks, pooled AUC, logreg | rf): 2018 embedding 0.945 | 0.940; dNDVI set 0.890 | 0.894; both 0.948 | 0.942. Pre-set criteria S0 pass, S1 pass (A-B +0.054, block-bootstrap CI [+0.036, +0.073]), S2 fail. Label-permutation AUC ~0.50. Block size 1/3/5 km changes nothing.
- 2026-11-11: Post-hoc controls (added after seeing A>B, not pre-set): 2017 embedding alone 0.848 | 0.781, pre-event NDVI alone 0.595 | 0.550, embedding change 2018-2017 0.901 | 0.904. Interpretation of the 2017 control was corrected by the next test: the 11 site factors alone only reach 0.62, so the 2017 result is probably not site information; the 2017 layer includes Dec 2017, about a month after the event, so it is not pre-event.
- 2026-11-11: Objective set to detection (replace manual digitizing), not susceptibility. Site-controlled test (src/site_controlled_check.py; 11 Mendeley factors added to every set; same CV; AUC logreg | rf): factors alone 0.625 | 0.621; dNDVI+factors 0.895 | 0.912; embedding change+factors 0.900 | 0.907; both+factors 0.924 | 0.934; 2018 embedding+factors 0.938 | 0.939 (not pre-set). Pre-set criteria: D0 pass, D1 fail (embedding change vs dNDVI: +0.005 | -0.005, CI spans 0, a tie), D2 pass (adding embeddings to dNDVI: +0.024 | +0.022, CI excludes 0). Embeddings are complementary, not better alone. Caveats: 1:1 matched points, not realistic prevalence; v1.0/v1.1 version artifact (M3) unresolved.

- 2026-11-11: POC passed in modest form (embeddings complementary to dNDVI, not better alone). Full plan approved: docs/plan.md (screening aid; full-area 10 m detector on the Mendeley factor grid; object-level recall >= 80% for slides >= 5 px at precision >= 30% on held-out 3 km blocks; stack downloaded locally).
- 2026-11-11: Phase 1 done (gate: `make data` rebuilds from raw, bad pixels counted, test IDs stored). Stack on the Mendeley factor grid in data/interim/ (gitignored): emb2017/emb2018 uint8 (value = (v - 128) / 127; EE counted 2 bytes per uint8 value, so 560 px tiles; norm 0.984 to 1.015, 0 missing), ndvi float32 (pre / postA / postB; no cloud-free pixel: 70 / 14,514 / 0 of 13.70 M). Domain 13.70 M px (1,370 km2) = valid land use, with geology, minus the 5 unmapped blocks. Labels: 21,500 positive px (0.157%), 20 m exclusion ring; 14 of 743 polygons have no centre pixel (object level by overlap). Test set: 34 of 170 3 km blocks (20%, seed 42, stratified by positive count; 26 sliver blocks train only; 5,399 of 21,097 positive px), IDs in data/interim/test_blocks.json; loader src/data/load.py refuses the test side without LANDSLIDE_FINAL_EVAL=1. Community tier = 150 EECU-hours per month; the full download (3 layers, about 30 min) hit no limit.
- 2026-11-11: Found a registration offset: the inventory polygons sit about 9.4 m south and 8.4 m west of the Sentinel-2 / embedding grid (vegetation-loss AUC of the positive pixels peaks there; 7.5 to 10.5 m N/E in four regional halves, so one rigid shift). Cause unverified (datum or georeferencing). Labels are shifted in src/data/labels.py; residual offset after the shift 0.01 px; pixel AUC of -dNDVI 0.825 -> 0.856. Delivery note: predicted polygons are on the Sentinel-2 grid, shift back by (-8.4, -9.4) m to compare with the manual inventory.
- 2026-11-11: POC re-run on aligned features (src/data/features_from_stack.py + site_controlled_check; AUC logreg | rf): dNDVI+factors 0.918 | 0.935; embedding change+factors 0.888 | 0.903; both+factors 0.929 | 0.947; 2018 embedding+factors 0.942 | 0.943. The POC dNDVI numbers were understated (misaligned sampling). D1 now fails the other way (dNDVI beats embedding change by 0.030 | 0.032, CI excludes 0; small slides < 5 px 0.82 vs 0.89 to 0.91), D2 still passes but halves (+0.011 | +0.012). Regression vs POC: embedding sets within 0.01, dNDVI sets +0.026 | +0.023 (fails the +/-0.01 criterion as written, explained by the offset). Candidates change: drop the embedding change and the 2017 layer; compare (a) dNDVI + factors, (b) 2018 embedding + factors, (c) 2018 embedding + dNDVI + factors.

- 2026-11-11: Phase 2 EDA done (gate; reports/eda.html, tables in reports/tables/, script src/analysis/eda.py, training blocks only, 16,101 positive px, 586 polygons, prevalence 0.15%). Hypotheses written first: 8 of 10 expected directions held, 4 of 10 sizes; surprises: dB / postB / postA are far stronger than expected (pixel AUC 0.86 to 0.89 for -dB, postB), spi 0.71 (collinear with slope 0.71), distroad opposite (slides farther from roads), distriv moderate, curvature and aspect weak not null. Binned: landslide share 1.14% in the lowest dB decile vs 0.04% from decile 3 up; share drops in the most remote road decile (0.24% to 0.11%), a sign of under-mapping. Naive -dNDVI detector (pixel level, training): precision 19% at 20% recall, 7% at 50%, 0.6% at 80% (flags 19% of the area). Its false alarms sit in land-use classes 10, 11 and 2, not near rivers (59% vs 58% within 100 m), so land use is a false-alarm filter. Moran's I of block share 0.07 / 0.07 / 0.23 at 1.5 / 3 / 6 km: report 6 km blocks as a sensitivity check. 2018 embedding: PCs 1 to 3 separate landslides (AUC 0.31, 0.70, 0.17). VIF: pre 12.5, all others < 10.
  Cleaning rules: domain (50,669 + 431,721 px out), 20 m ring (37,929 px), postA gaps median-fill + flag (about 11,700 px), twi gaps fill + flag (about 1,700 px), pre/dB gaps drop (about 36 px), no outliers removed. Constraints: effective sample = polygons (586), not pixels; judge by precision-recall and object metrics; ~26% of polygons < 5 px and 14 have no centre pixel; distroad and land use carry reporting signal, run with and without. Ideas ranked: (1) 3x3/5x5 neighbourhood stats of dB and postB, (2) land use as false-alarm filter with dB interactions, (3) monotone-constrained boosting vs regularised logistic baseline, (4) embedding PCs / regularised logistic, (5) geology target-encoded inside folds, (6) slope flag below ~5 deg. Open: land-use and lithology class names and map year, roads' dates, whether remote under-mapping is real (footprint).
- 2026-11-11: Phase 3 done (gate: `make features` builds the table and runs the checks). 97 features in 6 groups (ndvi_pixel, ndvi_nbr, terrain, site_cat, flags, emb), registry with hypothesis and expected sign in src/features/registry.py, catalogue in reports/tables/feature_catalogue.csv. One tile-wise code path (src/features/build.py, 512 px tiles with a 5 px halo, NaN neighbours replaced by fixed constants) will also serve full-area prediction. Training table data/interim/features_train.parquet: 16,101 positive + 400,000 negative pixels from training blocks only (negative weight 26.7), 22 s to build; missing values stay NaN, fills = training medians in fill_values.json, flags kept. Checks (src/features/check.py): no constant, all-zero or too-good (AUC outside 0.05 to 0.95) feature; no identifier columns; tile invariance exact (and fails with halo 0, so the test works); neighbourhood stats match a plain-loop recomputation (max diff 4e-6); observed signs match the registry; permuted-label block-CV AUC 0.498. Neighbourhood minima beat the single pixel: -dB_min5 AUC 0.91 vs 0.86 for dB. Bug found and fixed: spi is already log-scaled in the source (range -8 to 7), log1p had turned 7% of it into NaN (also fixed in the EDA histogram and outlier rule; AUCs and correlations were rank-based and unaffected). emb2017.tif deleted (unused); `make data` no longer downloads it. Constraint for phase 5: the 24 neighbourhood features are highly collinear, so linear models need regularisation or a reduced set (VIF rule), and feature groups are added or dropped as groups in the ablation.
